# control-routes-provider 1.0

Namespace: `port1/systems/zero/capability-interfaces/control-routes-provider`

Control route providers carry dispatch results and attribute reports between an integration and Port OS. Use them to report acknowledgements, errors, deferred responses, and batches of messages.

Read scopes: endpoint:read. Inbound control scope: message:send. Resource permission is also required.

[Complete YAML](/docs/references/capability-interfaces/control-routes-provider/1.0.yaml)

## Messages

- [acknowledged](/docs/references/capability-interfaces/control-routes-provider/1.0/messages/acknowledged.yaml) (in): Response to acknowledge a message was dispatched, it confirms that a message was dispatched, but not necessarily that it did anything.  Consider this to happen on any infrared based device (TV remotes), where no ack is feasible.
- [attribute-report](/docs/references/capability-interfaces/control-routes-provider/1.0/messages/attribute-report.yaml) (in): Response to report attributes of a control route
- [batch-message-dispatch](/docs/references/capability-interfaces/control-routes-provider/1.0/messages/batch-message-dispatch.yaml) (in): Request to dispatch a batch of messages to a control route sent from port OS to the control routes provider
- [deferred-response](/docs/references/capability-interfaces/control-routes-provider/1.0/messages/deferred-response.yaml) (in): Response to acknowledge a message was dispatched, it confirms that a message was dispatched, and that a confirmation of the result will be sent later on.  We generate this message when the device is expected to respond some time later on, and we need to wait for the result.  For the default behavior, we expect to wait up to a minute to handle low powered devices.
- [error-dispatch](/docs/references/capability-interfaces/control-routes-provider/1.0/messages/error-dispatch.yaml) (in): Response to acknowledge a message was dispatched, it confirms that a message was dispatched, and that the result was not successful.
- [report-attributes](/docs/references/capability-interfaces/control-routes-provider/1.0/messages/report-attributes.yaml) (in): Request to report attributes of a control route sent from port OS to the control routes provider
- [successful-dispatch](/docs/references/capability-interfaces/control-routes-provider/1.0/messages/successful-dispatch.yaml) (in): Response to acknowledge a message was successfully dispatched, it confirms that a message was dispatched, and that the result was successful.
